# Bundled legal corpus data dictionary

The bundled search engine reads a JSON array. Each entry contains one passage and the metadata used to retrieve, display and cite it. See the [corpus](../backend/rag/data/processed/canonical_corpus.json) and the [chunk definition](../backend/rag/ingest/chunker.py). Database-backed legal sources have a separate [schema](DATABASE.md).

| Fields | Meaning |
| --- | --- |
| `chunk_id` | Identifier generated by the chunker, for example `chk_const_article_21_91efbdea`. |
| `source_id`, `source_url` | The registry identifier and the URL provided with the passage. Some URLs point to a publisher's portal. |
| `doc_type` | The bundled records include statutory passages (`STATUTE`), procedural guidance (`PROCEDURE`) and judgment summaries (`JUDGMENT`). |
| `act`, `short_code`, `section`, `clause_heading`, `chapter` | Display title and optional identifiers locating the material within a source. |
| `jurisdiction`, `language`, `topic_tags` | Territorial scope, language code and topical keywords for the entry. |
| `version`, `in_force`, `effective_date`, `repealed_by` | Edition and status recorded by the corpus author. The effective date and successor can be null. Search filters out entries marked out of force by default. |
| `chunk_text`, `token_count` | Indexed passage, which can include a heading or summary, and its estimated length in tokens. |
| `content_checksum` | SHA-256 of the indexed text used to match a citation to a passage. |

The [source registry](source_registry.csv) records source details. The [concordance table](../backend/rag/ingest/concordance_table.py) supplies the known older provision references used in [query expansion](../backend/rag/search/query_rewriter.py).
